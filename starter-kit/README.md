# Стартовый набор: usedesign в вашем репозитории за час

Это инструкция для команды, которая видит usedesign впервые. Всё нужное лежит в этой папке —
копируйте к себе и правьте под свой репозиторий. Подробная теория — в [SPEC.md](../SPEC.md);
сюда вынесено только то, без чего не начать.

## Что это, в пяти предложениях

Каждая операция системы описывается **одним файлом** — карточкой: что делает, какими шагами,
каким тестом доказана, что делает с данными. Инструмент `usedesign` сверяет карточки не с
чьими-то словами, а с тем, что система **говорит о себе сама**: со списком маршрутов её
собственного OpenAPI, с отчётом её собственного тестового прогона. Карточка, обещающая
несуществующее, и маршрут, не описанный никем, становятся строками в сводке CI — в тот же
день, а не через год. Исходники при этом не разбираются никогда: только живые ответы системы.
Врать формату можно — но дорого и недолго.

## Час первый: проверки 1–3 (только OpenAPI + отчёт тестов)

**Шаг 0. Инструмент не ставится — он зовётся:**

```bash
npx usedesign@0.15.0 --help
```

Версию закрепляйте (`@0.15.0`, не `latest`): проверка, которая молча меняет своё поведение
без правки в вашем репозитории, — сама по себе класс дефекта.

**Шаг 1. Каталог и конфиг.** Создайте в корне репозитория `usedesign/`, положите туда
[usedesign.config.yaml](usedesign.config.yaml) из этой папки и поправьте пути.

**Шаг 2. Перечень маршрутов.** Поднимите своё приложение, снимите его OpenAPI-документ и
превратите в перечень скриптом [tools/inventory-from-openapi.py](tools/inventory-from-openapi.py).
⚠️ **Граница этого пути** (замерена на живом сервисе): OpenAPI показывает только то, что
разработчик решил опубликовать — маршрут, скрытый из документации (`ExcludeFromDescription()`
и родня), в перечень не попадёт, и проверка №1 его не увидит. Честный источник по SPEC —
собственная таблица маршрутов фреймворка (в ASP.NET — `EndpointDataSource` через служебную
ручку, живущую только в Development). Скрипт из OpenAPI — дешёвый старт первого часа; перечень
подписывает свою границу сам:

```bash
curl -fsS http://localhost:8080/openapi/v1.json -o /tmp/openapi.json
python3 usedesign/tools/inventory-from-openapi.py /tmp/openapi.json usedesign/route-inventory.json
```

**Шаг 3. Отчёт тестов.** Прогоните тесты с JUnit-выводом — его умеют почти все раннеры
(`dotnet test --logger junit`, `jest --reporters=jest-junit`, `pytest --junitxml=...`).
⚠️ **Зелёный прогон — ещё не свежий отчёт**: обычный `npm test` / `vitest run` файл JUnit НЕ
пишет, и проверка судит вчерашнего свидетеля. Ловушка замерена пилотом (issue #9): встречная
проба «опровергла» гипотезу только потому, что отчёт не был снят заново. Перед каждым замером —
перегенерируйте отчёт той же командой, что в гейте.

**Шаг 4. Первая карточка.** Возьмите за образец [examples/library/](../examples/library/) —
пять разобранных карточек живого фасона. Начните с ОДНОЙ операции, которую знаете лучше всего.
Правило, на котором всё держится: **строка карточки пишется по замеру кода, не по памяти о
нём.** Проверьте себя:

```bash
npx usedesign@0.15.0 validate usedesign/cards/
npx usedesign@0.15.0 check usedesign/usedesign.config.yaml
```

Сотни строк «маршрут не описан никем» в первом прогоне — это норма и есть смысл: теперь
неописанное ВИДНО. Заготовки для остальных маршрутов генерируются командой
`npx usedesign@0.15.0 scaffold <openapi.json> --out usedesign/drafts` — каждая заготовка
нарочно не проходит валидацию, пока человек её не дозаполнит и не перенесёт в `cards/`.

**Шаг 5. Гейт.** Скопируйте [usedesign-gate.yml](usedesign-gate.yml) в
`.github/workflows/`, поправьте отмеченные места. Гейт стартует в **режиме отчёта**:
расхождения печатаются в сводку прогона, сборка не валится. Это намеренно — строгий гейт на
сотне неописанных маршрутов выключили бы в первый же день. Строгость включается одной строкой,
когда неописанного останется около нуля.

## Вторая волна (когда первая приживётся)

- **Проверка №4 — хранилище**: карточки заявляют, какие таблицы трогают, перечень снимается с
  живой базы. SPEC §7.4.
- **Проверка №5 — контракты форм**: владелец продукта описывает, что экран ОБЯЗАН показывать;
  тест рендерит настоящие компоненты и сверяет. Ошибки этого гейта — список дел продукта, а не
  поломка. Самая сильная и самая требовательная часть. SPEC §7.5.
  **Производитель перечня — рецепт готов** (закрыл issue #7, где пилот застрял ровно тут):
  скопируйте [formInventory.recipe.test.tsx](formInventory.recipe.test.tsx) и правьте места
  «ПОД СЕБЯ». Рендер по состояниям — ваш; конвенция якорей (data-field / data-section /
  data-panel-head / data-action / data-control) и формат перечня — в коробке:
  `import { collectScreenState, mergeStates, stateEntry, formInventoryDocument } from 'usedesign'`.
  Помощник обходит настоящий DOM, пишет и цепочки контейнеров (`within`) — с ними проверка
  сверяет ещё и СОСТАВ групп контракта.
- **Фронтовый репозиторий** объявляет в конфиге `checks: [5]` — проверки маршрутов и хранилища
  там бессмысленны и потому отключены гласно. SPEC §7.6. Карточки операций при этом живут у
  сервера, и каждый `calls:` контракта в гейте фронта — честное предупреждение «карточки не
  видно». Чтобы правило «контрол показан ровно в состояниях, откуда уходит операция» заработало и
  в CI, гейт фронта забирает соседний репозиторий вторым `checkout` (закомментированный шаг в
  [usedesign-gate.yml](usedesign-gate.yml)) и добавляет его карточки в `cards:`. Замерено на двух
  наших репозиториях: три предупреждения → ноль.
- **Превью контрактов**: `npx usedesign@0.15.0 preview usedesign/usedesign.config.yaml --out
  preview.html` — страница с деревом форм, текстом контракта и грубым каркасом, где у каждого
  элемента вердикт «есть / нет в коде / вне контракта».

## Что здесь сырое — честно

1. **Обкатано на одном продукте плюс один чужой пилот** (один сервер + один фронт, двадцать
   раундов обкатки; последние два раунда целиком продиктованы пилотом на чужом стеке — одиннадцать
   issues, все закрыты). Ваш стек почти наверняка сломает что-то, чего мы не видели, — у нас
   каждый второй раунд начинался именно так. Ломается — несите: правка формата = схема + оба
   сверщика + случай в корпусе, это отработанный цикл.
2. **Версия 0.x.** Несколько раундов подряд формат меняется только необязательными полями, но
   право на ломающее изменение пока не сдано. Пин версии в гейте защищает вас полностью.
3. **Инструмент ловит форму, не честность.** Карточку, красиво врущую о том, что код делает
   (в полях, которые ни с чем не сверяются: провенанс, обратимость), поймает только ревью.
   Культура «по замеру, не по памяти» — обязательная часть поставки.
4. Проверка №4 требует доступа к живой базе там, где идёт прогон; проверка №5 — теста,
   который рендерит ваши настоящие компоненты. Обе — вторая волна не случайно.
